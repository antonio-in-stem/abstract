Diagnostics

When Abstract says no.

Every failure has a stable identifier, a project-relative position and one sentence of explanation. This is the whole catalogue.

Reference
Grammar Diagnostics CLI Compiled data

Reading a diagnostic

<path>:<line>:<col>: error[<ID>]: <message>
  note: <note text>
data/products/atlas.ab:4:5: error[E409]: Unknown field 'rarty' in atlas. Did you mean 'rarity'?
  note: declared fields: title, status, rarity, owner.

The path is project-relative with / separators; absolute, canonical and extended-length platform paths never appear. Line and column are 1-based and the column counts Unicode scalar values. The message is one sentence ending with a period. Notes are indented two spaces and each may name a second position, such as the first declaration site of a duplicate.

When a diagnostic has no meaningful column the form is path:line: error[...]; with no position at all, path: error[...]; and when it concerns no file, abstract: error[...].

Substitutions

PlaceholderRendered as
{context}the dotted path of the containing object, rooted at the instance id: atlas, atlas.owner, atlas.copy[2]
{field}the normalised field name
{kind}one of text, int, float, bool, enum, file, image, ref, object, list, absent
{versions}a set of versions as ascending maximal ranges: 1..2, 4
{value}a scalar rendered exactly as JSON would render it
listsitems in declaration order, unquoted, separated by ,

Suggestions

A diagnostic offers Did you mean when a candidate is close enough: the Levenshtein distance between the normalised texts must be at most 2 and at most half the length of the offending text. The smallest distance wins, broken by declaration order where the candidate set has one. When no candidate survives, the clause is omitted entirely.

Which error comes first

When one input satisfies more than one condition, the reported diagnostic is chosen by, in order: the earliest compilation phase; within a phase, the earliest step; within a step, the earliest source position; and at the same position, the lower identifier.

These pairs are fixed explicitly, because both conditions can arise in the same step: E443 before E412; E211 before E412 and E413; E603 before E430 and E440; E430 before E440; E320 before E313; E807 before E804; E415 before E414; E445 before E411.

--max-errors bounds how many are reported (default 20, 0 for no limit). The ones reported are always the first in that order, so the flag never changes which diagnostic comes first and never changes the exit code. When it stops early, the final stderr line is abstract: note: stopping after {n} errors; more may remain.

Exit codes

CodeMeaning
0success
1compilation failed: at least one E1xx–E7xx diagnostic
2usage error: an E8xx diagnostic other than E810
3output could not be written (E810)

When an error names a schema field, trust the schema first and fix the source around it. When it names a line and a column, start exactly there — the position is part of the contract, not a hint.
