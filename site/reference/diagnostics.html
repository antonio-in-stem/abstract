Diagnostics

When Abstract says no.

Every failure mode has a predictable message. Parse problems carry file and line (stickers/bad.ab:3:); validation problems carry file and field context. This page explains what each kind of problem means.

Reference
Grammar Diagnostics CLI RAW

Unknown template

abstract: data/item.ab: unknown template 'Product'

The instance header names a schema that was not found. Check spelling, file extension, and whether the schema file is inside the compiled directory.

Missing required field

abstract: data/atlas.ab: Product.owner is required

A field has no default and is not marked optional. Add the assignment, mark the field optional, or provide a schema default.

Enum mismatch

abstract: data/atlas.ab: Product.status received 'public', expected one of: draft, active, retired

The value is not part of the schema vocabulary. Do not invent new enum values in an instance; add them to the schema only when the vocabulary really changed.

Range mismatch

abstract: data/atlas.ab: Product.release_year value 1800 is outside allowed range 2000..2100

The value is outside the numeric range, or a text value has a length outside the allowed character count.

Unknown field (typo protection)

abstract: stickers/typo.ab: Unknown field 'rarty' at Sticker. Did you mean 'rarity'?
Declared fields: id, rarity, origin, ...

Strict mode rejects fields the schema does not declare and suggests the closest declared name. Use --allow-unknown only during migrations.

Duplicate ids and schemas

abstract: things/b.ab:1: Duplicate instance id 'same'. It is already declared in 'things/a.ab' (line 1)
abstract: templates/B.abt: Duplicate schema 'Thing'. It is already defined in 'templates/A.abt'

Every instance id and every schema name must be unique across the compiled project. The error names both definition sites.

File extension mismatch

abstract: data/atlas.ab: Product.image has extension 'gif', expected png, jpg

The file path extension does not match the file(...) declaration.

Image mismatches

Image size mismatch at Sticker.icon: './icons/small.png' is 16x16, but this schema allows only: png 32x32.
Image content mismatch at Sticker.icon: './icons/fake.png' is named .png but its header is gif data.

image(...) fields probe the real file header. Size mismatches report the actual dimensions; content mismatches mean the file was renamed or exported with the wrong format.

Tuple arity mismatch

abstract: pages/bad.ab:3: tuple arity mismatch in 'copy': declared 2 column(s) (key, value), found a tuple with 3 value(s)

A tuple row has more or fewer values than the declared columns. A missing quote around a value containing commas is the usual cause.

Clone problems

abstract: clone cycle detected for 'atlas'
abstract: things/b.ab:1: clone path '&hero.stats' not found on the source instance

Cycles need a shared base instance instead of mutual clones. A missing clone path means the source instance never defined that subtree.

Bundle errors

abstract: bundle authentication failed (wrong key or modified data)
abstract: bundle claims to be unencrypted but a key was provided; refusing the downgrade

The first means a wrong key or a tampered file; the second is downgrade protection, a loader holding a key refuses plain bundles.

Schema parse errors

Errors such as invalid schema line, schema is missing a name, or schema block was not closed usually mean a typo in a .abt file, and carry the line number. Check braces first; most strange schema errors start there.

When an error names a schema field, trust the schema first and fix the source around it. When it names a line, start exactly there.
