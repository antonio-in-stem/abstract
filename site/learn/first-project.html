Tutorial

Your first Abstract project.

This walkthrough creates a small product catalog. It is intentionally ordinary; the point is to see the language do useful work without ceremony.

Learn
Overview First project Language guide CLI

1. Create folders

mkdir abstract-demo
cd abstract-demo
mkdir templates data build

2. Write a schema

Create templates/Product.abt:

schema Product {
    id: text(1..40)
    name: text(1..80)
    status: enum(draft, active, retired) = draft
    release_year: int(2000..2100)

    owner {
        team: text(1..50)
        contact: text(1..80)
    }

    capabilities[] {
        id: enum(search, sync, export) @tag
        availability: enum(alpha, beta, stable) = stable
    }
}

3. Write an instance

Create data/atlas.ab:

Product :: @id.atlas, @status.active
    name: Atlas Search
    release_year: 2026
    owner.team: Knowledge Systems
    owner.contact: systems@example.com
    capabilities: [#search, #sync(availability: beta)]

4. Lint the project

abstract lint .

Expected output:

abstract: ok

5. Compile JSON

abstract compile . JSON true

The output will include defaults and expanded tagged objects:

data: [
    {
        template: "Product",
        id: "atlas",
        name: "Atlas Search",
        status: "active",
        release_year: 2026,
        owner: {team: "Knowledge Systems", contact: "systems@example.com"},
        capabilities: [{id: "search", availability: "stable"}, {id: "sync", availability: "beta"}]
    }
]

6. Break it on purpose

Change @status.active to @status.public and run lint again. The compiler should reject it because public is not declared in the enum.

7. What just happened?

You authored compact source, but shipped validated output. The schema carried the rules; the instance stayed readable; the compiler caught the bad value before another tool had to guess what you meant.
