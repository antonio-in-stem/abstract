Tutorial

Your first Abstract project.

Two files, one command, and then a mistake on purpose. Fifteen minutes end to end.

Learn
Overview First project Language guide CLI

1. Scaffold

Every project is a directory. Sources live under data/, and binary assets under assets/. Create the two files by hand, or let the compiler do it:

abstract init m-project

The tutorial below builds the same shape from scratch. It is checked in as docs/examples/hello.

m-project/
  data/
    templates/Label.abt
    labels/hello.ab

2. Describe the shape

data/templates/Label.abt declares one schema with one field. The range counts Unicode scalar values, so a caption must be between 1 and 40 characters long.

schema Label {
    caption: text(1..40)
}

3. Write an instance

data/labels/hello.ab declares one object. The name before :: must be a declared schema; @id.hello gives the object its id. Without an @id tag the id would come from the file name, which here would also be hello.

Label :: @id.hello
    caption: "Hello, world"

The value is quoted for a reason. At bracket depth 0 a comma always separates list items, whatever the field’s type, so caption: Hello, world would be a two-item list and would fail with E412 on this non-list field.

4. Compile

abstract compile m-project JSON
{
  "abstract": {
    "format": 1,
    "compiler": "1.0.0",
    "versions": {
      "min": 1,
      "max": 1
    }
  },
  "data": [
    {
      "template": "Label",
      "id": "hello",
      "caption": "Hello, world"
    }
  ],
  "overlays": []
}

Three things to notice. The document has an envelope: abstract describes the document, data holds the objects for the newest version, and overlays holds the differences for older versions — empty here, because this project declares no version range. Every object begins with template and id, which the compiler writes and you never author. And the remaining keys follow the schema’s declaration order, not the order you wrote the assignments.

5. Validate without output

lint does exactly the same work — including asset checks — and renders nothing. On success it writes one line to stderr:

abstract lint m-project
abstract: ok

templates lists the schema names of the project, one per line, sorted:

abstract templates m-project
Label

6. Break it on purpose

Change the instance to use a field the schema does not declare:

Label :: @id.hello
    captoin: "Hello, world"
data/labels/hello.ab:2:5: error[E409]: Unknown field 'captoin' in hello. Did you mean 'caption'?
  note: declared fields: caption.

That is the shape of every diagnostic: a project-relative path, a 1-based line and column, a stable identifier, one sentence, then notes. The exit code is 1. Nothing is written to stdout.

Now try a value that is too long, or a quoted number on a numeric field, and read what comes back. Every identifier is catalogued in diagnostics.

7. Add a rule

Constraints that depend on relationships between fields go in a logic block, in a .abt file:

schema Label {
    caption: text(1..40)
    shout: bool = false
}

logic Label {
    require length(.caption) <= 20 or not .shout
        else throw "A shouted label must be short."
}

Logic runs after defaults and before the required-field check, so a derive can satisfy a required field. A failed require stops the compile with your own message and E515. This version of the project is checked in as docs/examples/hello-rule.
