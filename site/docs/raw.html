Compiled data

A contract, not a dump.

The compiled document is the only artifact consumers read. Its envelope, its key order, its number spelling and its overlay rules are all fixed by the specification, byte for byte.

The envelope

Every compiled document has exactly three top-level keys, in this order.

KeyValue
abstractmetadata about the document itself: format, compiler, versions
datathe compiled instance objects for the maximum version
overlaysthe differences for every earlier version, possibly empty

format is exactly 1 and changes only when the shape of the document changes, so a consumer that understands format 1 understands every document a 1.x compiler produces. compiler identifies the producer and is the only part of a document that is not a function of the source bytes.

Instance objects

Every object begins with template and id, then the schema’s fields in declaration order, skipping absent fields. Groups and $(Schema) values order their own keys by their own declaration order, recursively. There are no other keys: unknown fields cannot reach the output.

Key order therefore never depends on assignment order, clone order, or the order in which logic wrote values. Objects are ordered by (template, id), compared as sequences of Unicode scalar values, so the document never depends on file layout, directory names or command-line order.

There is no null

No format ever emits null, ~ or an empty value for a field. An absent optional field is omitted, for every type, including lists: an optional list that was never assigned does not become []. An empty list is a present value spelled []. A group is present when at least one of its own fields has a value, and omitted otherwise, so an empty object never appears anywhere in a conforming document.

A consumer distinguishes “absent” from “empty” by key presence.

The same tree, three ways

This is docs/examples/formats, stored with all three renderings.

schema Product {
    price: float(0..9999)
    featured: bool
    tags[]: enum(core, public, internal)
    capabilities[] {
        id: enum(search, sync) @tag
        availability: enum(alpha, beta, stable) = stable
    }
}

Product :: @id.atlas
    price: 19.5
    featured: true
    tags: [core, public]
    capabilities: [#search]

JSON

Two-space indent; a non-empty object or array puts each member on its own line and closes at the parent’s indentation; an empty object is {} and an empty array [] on one line; the separator is ": "; exactly one trailing LF, no BOM, no trailing whitespace on any line.

{
  "abstract": {
    "format": 1,
    "compiler": "1.0.0",
    "versions": {
      "min": 1,
      "max": 1
    }
  },
  "data": [
    {
      "template": "Product",
      "id": "atlas",
      "price": 19.5,
      "featured": true,
      "tags": [
        "core",
        "public"
      ],
      "capabilities": [
        {
          "id": "search",
          "availability": "stable"
        }
      ]
    }
  ],
  "overlays": []
}

YAML

Block style, two-space indent, and every mapping key double-quoted — which is what makes a field named 1, yes, no, on or null unambiguous. Numbers and booleans are bare. No --- marker; exactly one trailing LF.

"abstract":
  "format": 1
  "compiler": "1.0.0"
  "versions":
    "min": 1
    "max": 1
"data":
  - "template": "Product"
    "id": "atlas"
    "price": 19.5
    "featured": true
    "tags":
      - "core"
      - "public"
    "capabilities":
      - "id": "search"
        "availability": "stable"
"overlays": []

RAW

A review format: the same data with bare keys and four-space indent, for diffs and code review. It is not intended to be machine-parsed, and no Abstract tool reads it back. The envelope is rendered without its outer braces; an object is always multi-line; an array of scalars is inline and an array containing an object or array is multi-line.

abstract: {
    format: 1,
    compiler: "1.0.0",
    versions: {
        min: 1,
        max: 1
    }
},
data: [
    {
        template: "Product",
        id: "atlas",
        price: 19.5,
        featured: true,
        tags: ["core", "public"],
        capabilities: [
            {
                id: "search",
                availability: "stable"
            }
        ]
    }
],
overlays: []

Numbers

Integers render in base ten with no leading zeros (except 0), with - for negatives and never +. The full signed 64-bit range is representable.

Floats render as the shortest decimal string that round-trips to the same binary64 value, then:

ValueRendered
zero0.0, or -0.0 for negative zero
1e-6 ≤ |v| < 1e21plain positional, with .0 appended when there are no fractional digits — so 3 renders 3.0
anything elsescientific: one digit, ., at least one fractional digit, e, an explicit sign, no leading zeros in the exponent (1.0e+21, 1.5e-7)

A float is therefore always distinguishable from an integer. Non-finite values cannot occur.

Strings

In all three formats a string is emitted between double quotes with exactly these escapes: \", \\, \b, \t, \n, \f, \r, and \u00XX in lowercase hexadecimal for any other C0 or C1 control character. Every other Unicode scalar value, including all non-ASCII text, is emitted literally as UTF-8. / is never escaped.

Enum values are always the normalised member name, so compare against lowercase, _-separated text. A ref value is the referenced instance’s id as a string; the referenced object is never inlined.

Overlays

Each overlay has exactly three keys, in this order: versions (an object with min and max), data (complete instance objects that replace or add to the base over that range, ordered by (template, id)), and removed (the ids of base objects that do not exist over that range, ascending). All three are always present; either array may be empty, but not both.

To read version v: start from data, then apply every overlay whose range contains v — replace or add each object by id, then delete every id in removed. There may be none, one or several. Ranges of different overlays may overlap, but for any single id the ranges that mention it are disjoint, so the order of application does not matter.

Determinism

For a fixed set of source bytes one compiler emits byte-identical output regardless of filesystem enumeration order, the spelling of the command-line roots, the platform, path separator convention, locale, time zone or environment, whether --skip-assets was passed, and whether the compile was whole-project or single-file. Two implementations differ only in the abstract.compiler string.

Practical notes

  • Look up by id. Ids are unique project-wide and normalised, so they are stable join keys; template says which schema the object satisfies.
  • Treat key presence as the only absence signal. There is no null and no sentinel.
  • Do not infer a type from a value. A text field holding 19.5 is the string; a float field holding 3 renders 3.0. The schema is the contract.
  • Pin abstract.format. Refuse a document whose format you do not understand rather than guessing.
  • Do not parse RAW. Read JSON, or YAML if your pipeline prefers it.
