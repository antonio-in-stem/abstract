Compiled data

The output is part of the language.

Abstract emits standard JSON or YAML after validation and normalization. The authored language stays compact; the compiled artifact stays easy for other tools to consume.

Top-level format

{
  "data": [
    {
      "template": "Product",
      "id": "atlas",
      "status": "active"
    }
  ]
}

The top-level value is always data, followed by an array of compiled objects. Each object includes template and id.

Ordering

Object fields are ordered predictably: template, id, then schema fields in the order they were declared. Extra fields, when they exist, stay after schema fields. This makes reviews calmer because unrelated fields do not jump around.

Normalization

InputOutput behavior
Bare enum valuesNormalized to lowercase snake case.
Integer-like stringsConverted to numbers when the schema expects int.
Missing defaultsInserted before output.
Optional missing listsEmitted as empty arrays.
Tagged shorthandExpanded into objects with the tagged field filled.
Wildcard tagged valuesExpanded against matching enum values.

Strings

Strings are quoted in JSON and YAML output. Backslashes and quotes are escaped. Bare words in source may become strings in output after schema validation.

Arrays and objects

JSON uses brackets and braces. YAML uses indentation. Both formats preserve the same validated structure.

What compiled data is good for

  • Reviewable generated data.
  • Build pipelines that want a stable intermediate artifact.
  • Language bindings that can parse a small, predictable shape.
  • Diffs where humans still need to understand the compiled result.

File writing

The compiler always prints the result. Add true as the final argument to also write a sibling .json or .yml file next to the first input.
