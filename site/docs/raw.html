Compiled data

The output is part of the language.

Abstract emits standard JSON or YAML after validation and normalization. The authored language stays compact; the compiled artifact stays easy for other tools to consume.

Top-level format

{
  "data": [
    {
      "template": "Product",
      "id": "atlas",
      "status": "active",
      "price": 9.5,
      "featured": true
    }
  ]
}

The top-level value is always data, followed by an array of compiled objects. Each object includes template and id. Numbers and booleans are native JSON values: an authored 9.5 is a number, an authored true is a boolean, never the strings "9.5" or "true".

The RAW text format

abstract compile <path> RAW emits the human-oriented .abraw form: same data, unquoted keys, four-space indentation. It exists for reviews and diffs where JSON punctuation is noise.

data: [
    {
        template: "Product",
        id: "atlas",
        status: "active",
        price: 9.5
    }
]

Ordering

Object fields are ordered predictably: template, id, then schema fields in the order they were declared. Nested groups and $(Schema) objects are also ordered by their schema. Extra fields, when they exist, stay after schema fields. This makes reviews calmer because unrelated fields do not jump around.

Normalization

InputOutput behavior
Bare enum valuesNormalized to lowercase snake case.
Integer-like stringsConverted to numbers when the schema expects int.
Decimal literalsKept as native floats (9.5); multi-dot values like 1.21.5 stay text.
true / falseKept as native booleans.
Missing defaultsInserted before output.
Optional missing listsEmitted as empty arrays.
Tagged shorthandExpanded into objects with the tagged field filled.
Wildcard enum valuesExpanded against matching vocabulary members.
$field interpolationResolved after clone overrides, before validation.

Strings

Strings are quoted in JSON, YAML, and RAW output. Backslashes, quotes, newlines, and tabs are escaped (\\, \", \n, \t, \r), so multi-line text round-trips safely. Bare words in source may become strings in output after schema validation.

Arrays and objects

JSON uses brackets and braces. YAML uses indentation. Both formats preserve the same validated structure.

What compiled data is good for

  • Reviewable generated data.
  • Build pipelines that want a stable intermediate artifact.
  • Language bindings that can parse a small, predictable shape.
  • Diffs where humans still need to understand the compiled result.

File writing

The compiler always prints the result. Add true as the final argument to write a sibling .json, .yml, or .abraw file next to the first input, or pass --out <file> for an explicit path.

Sealed bundles

When compiled data ships inside an application instead of a repository, abstract bundle seals the JSON document into an encrypted, tamper-evident .abx container. The Java & bundles page covers the format and the runtime.
