Instance authoring

The expressive half.

Instances are where Abstract earns its keep: compact headers, dotted paths, tables, shorthand tags and copy-by-clone, all checked against the schema.

Anatomy

Product :: @id.atlas, @status.active     <- header, with header tags
&base_product.*                          <- clone statements, if any
    title: Atlas Search                  <- body statements
    owner {                              <- body block
        team: Knowledge Systems
    }

A logical line is an instance header if and only if its first token is a schema name and the token immediately after it is ::. Nothing else starts an instance, so window: 12::30 is an ordinary assignment. A statement before the first header is E403, and a second :: inside a header is E436.

Header tags

FormMeaning
@name.valueassigns value to the root field name
@nameassigns true; the field must be bool, else E412

The value runs to the next depth-0 , or @; quote it to include one: @label."hi, there @world". It is interpreted by the field’s declared type exactly like a body value, so @count.12 is the number 12 on an int field and the string "12" on a text field.

A header tag addresses exactly one root field. Targeting a group, a list group or a $(Schema) field is E438, and a tag value can never be a list, a #tag object, a tuple row or a brace pattern — write those as body statements. Header tags are applied after every clone and before every body statement, so a tag always wins over a cloned value.

A long header may wrap after a comma. This is the one place a trailing comma continues a line:

Product :: @id.atlas,
           @status.active

Identity

Every instance has an id: the value of @id, or, in its absence, the file stem. It must be a valid identifier and is normalised, so @id.Winter-Pack is winter_pack and @id.42 is the string "42" — an id is never type-inferred.

Ids are unique across the whole project, across all templates (E402), and version windows do not partition the id space. One file may declare several instances, but the stem can serve only one of them, so all but one need @id.

Paths, multi-paths and blocks

This is docs/examples/paths-and-blocks.

Service :: @id.api
    title: API
    limits.{soft, hard}: 10
    owner {
        team: Platform
        contact: platform@example.com
    }
{
  "template": "Service",
  "id": "api",
  "title": "API",
  "limits": { "soft": 10, "hard": 10 },
  "owner": { "team": "Platform", "contact": "platform@example.com" }
}
RuleConsequence
the left side ends at the first : at bracket depth 0link: https://example.com keeps its colon
a dotted path creates intermediate objectsbut may not traverse a list field (E443)
no index syntax in an assignmentitems[0].x is E316
a body block is sugar for a prefixits { ends its line, its } starts one, and it joins no lines
a path is written oncewriting it twice in overlapping versions is E429, not last-wins

Values

The parser infers no types: it produces a syntax value, and the declared type of the target decides how it is read. Three spellings of the same list:

tags: [core, public]
tags: core, public
tags: [
    core,
    public
]

A trailing comma is allowed inside brackets and is E442 at depth 0. An empty list is []; an empty item (a,,b) or a nested list is E441.

caption: "Hello, world"       // one string
caption: Hello, world         // a two-item list; E412 on a non-list field
color: "#ff0000"              // quote it: a leading # starts a tag object
note: "[draft]"               // quote it: a leading [ starts a list
count: 5                      // int; count: "5" is E412

Quoted strings support exactly five escapes — \", \\, \n, \r, \t — and must open and close on the same physical line. There is no \u: write the character. Windows paths use / or \\.

Tagged objects

capabilities: [#search, #export(availability: alpha), #sync(limits.soft: 10)]

#name sets the group’s @tag field. Arguments are key: value or a bare identifier, which sets a bool field to true. A key may be a dotted path into the group’s own nested groups, and a value may be a bracketed list or another #tag. A bare comma-separated list is not available there, because the comma separates arguments. Text after the closing ) is E210: nothing is silently discarded.

Tuple arrays and wildcards

This is docs/examples/tables-and-wildcards.

schema Page {
    title: text(1..60)
    flags[]: enum(hat_small, hat_large, boot_small)
    images[]: image(png 16x16)
    copy[] {
        key: enum(en_us, es_es, es_mx) @tag
        value: text(1..80)
    }
}
Page :: @id.home
    title: Home
    flags: hat_*
    images: ./art/{hero,thumb}.png
    copy(key, value): (en_us, Welcome), (es_*, Bienvenido)
{
  "template": "Page",
  "id": "home",
  "title": "Home",
  "flags": ["hat_small", "hat_large"],
  "images": ["./art/hero.png", "./art/thumb.png"],
  "copy": [
    { "key": "en_us", "value": "Welcome" },
    { "key": "es_es", "value": "Bienvenido" },
    { "key": "es_mx", "value": "Bienvenido" }
  ]
}

Three constructs are at work. A tuple array names its columns once and lists rows; every row must have exactly as many cells as there are columns (E416). An enum wildcard expands in the enum’s declared order, and is legal in exactly three positions: an element of an enum list field, a tuple cell whose column is an enum, and the name of a #tag whose tag field is an enum. A brace pattern expands only in a value of a file or image list field.

A wildcard that matches nothing is E415; it never silently expands to nothing. Several brace groups produce the cartesian product, with the leftmost varying slowest, and groups do not nest.

Rows are separated by depth-0 commas, so an unbracketed tuple array is one logical line. Wrap the row list in brackets to spread it over several physical lines:

copy(key, value): [
    (en_us, Welcome),
    (es_es, Bienvenido),
]

Interpolation

This is docs/examples/interpolation.

Product :: @id.atlas
    title: Atlas
    image: ./textures/$id.png
    label: ${id}_display
    note: "$$99 special"
{
  "template": "Product",
  "id": "atlas",
  "title": "Atlas",
  "image": "./textures/atlas.png",
  "label": "atlas_display",
  "note": "$99 special"
}

The variables are the instance’s root scalar fields after clones and its own statements, plus id, which is always available. $name consumes the maximal run of identifier characters, so $id_large names id_large; write ${id}_large for the other reading. Substitution is a single left-to-right pass and never rescans what it inserted, so chained interpolation does not work. An unknown variable is E425 — a misspelling never reaches the output.

Clones

This is docs/examples/clones.

Product :: @id.atlas, @status.active
    title: Atlas Search
    owner.team: Knowledge Systems
    owner.contact: systems@example.com
    capabilities: [#search, #sync(availability: beta)]
Product :: @id.beacon
&atlas.*
    title: Beacon Export

beacon gets atlas’s status, owner and capabilities, and overrides the title. Clone statements must appear immediately after the header, before any body statement (E404); anywhere else a & line is an error, not a statement that quietly attaches to the next instance.

FormMeaning
&id, &id.*full clone
&id.pathpartial clone of that subtree

The source must exist (E405) and must use the same template (E407); cross-template clones do not exist. Cycles are E406. A clone copies the source’s authored data after its own clones — before defaults, before interpolation, before logic — so a value the source only receives from a default or a derive is not visible to a partial clone. template and id are never cloned, and interpolation runs after cloning, so a cloned ./textures/$id.png resolves to the cloning instance’s id.

Merging

Existing valueIncoming valueResult
absentanythe incoming value
objectobjectrecursive merge, key by key
keyed listkeyed listmerge by tag value; existing order kept, new keys appended
anything elseanyreplaced

That table governs clone-to-clone folding only. The instance’s own header tags and body statements are then applied by plain assignment: they replace whatever the clones left, with no merging, even for a keyed list. To extend a cloned keyed list rather than replace it, restate the whole list.

This is docs/examples/clone-merge:

Product :: @id.base_a
    title: Base A
    capabilities: [#search(availability: alpha), #sync]

Product :: @id.base_b
    title: Base B
    capabilities: [#search(preview), #export]

Product :: @id.merged
&base_a.*
&base_b.*
{
  "template": "Product",
  "id": "merged",
  "title": "Base B",
  "capabilities": [
    { "id": "search", "availability": "alpha", "preview": true },
    { "id": "sync", "availability": "stable" },
    { "id": "export", "availability": "stable" }
  ]
}

title is a scalar, so the second clone replaces it. capabilities is a keyed list, so search merges field by field, sync keeps its place, and export is appended. Two elements of one authored list sharing a key would be E444, so folding can never produce a list with two elements under one key.

Strictness

An instance may assign only fields its schema declares. An unknown field is E409 with a suggestion when the edit distance is at most 2, and a note listing the declared fields of the schema or group in scope. There is no lenient mode: --allow-unknown does not exist in 1.0.

data/products/atlas.ab:4:5: error[E409]: Unknown field 'rarty' in atlas. Did you mean 'rarity'?
  note: declared fields: title, status, rarity, owner.

Comments

// a whole-line comment
link: https://example.com          // a trailing comment; the URL is intact
note: "// not a comment"
cdn: "//cdn.example.com/x.png"     // quote to keep a leading //
ratio: "50 // 2"                   // quote to keep a spaced //

A comment starts at // only at the start of a line or immediately after a space or tab, and never inside a quoted string. There are no block comments, and comments never appear in compiled output.
