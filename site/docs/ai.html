Before writing anything

  1. Read the schemas first. Abstract is strict: an instance may assign only fields its schema declares, and there is no lenient mode. Never invent a field, an enum member or a schema name.
  2. Find the project root. It is the parent of the nearest ancestor directory named data, or the compiled directory when there is none. Assets live in <project root>/assets.
  3. Check the version range. If any .abt declares versions min..max, every version in that range must compile, not just the newest.
  4. Never write template: or id:. They are envelope keys the compiler writes. The id comes from @id.x or from the file name.
  5. Validate before claiming success. Run abstract lint, and abstract compile when the output matters. Quote the diagnostic verbatim if it fails.

Absence is uniform

An absent optional field is omitted from the output, for every type, including lists — it does not become [], and Abstract has no null in any format. In logic, an absent operand makes every comparison false, including !=; only exists distinguishes absence.

if .glow exists {
    require .glow == false else throw "glow must start off."
}

The reserved words

PositionWords
top level of a .abt fileschema, logic, versions
type positiontext, int, float, bool, enum, file, image, ref
modifier position@optional, @tag, @since, @removed
logic statement positionderive, derive?, require, if, else, for
logic expression positionin, not, and, or, contains, exists, length, version, true, false

Keywords are recognised only where they are meaningful; none of them is reserved as a field name, an enum member or an instance id. The document keys abstract, format, compiler, versions, data, overlays, removed, min and max are not reserved in the source language either.

Only two names are genuinely reserved, and only at the root of an instance object: template, which can never be declared or assigned, and id, which may be declared only as id: text or id: text(a..b) and can never be assigned. Inside a group both are ordinary field names.

Checklist before submitting a change

Schemas

  • Every schema name is unique project-wide; no field is named template; id, if declared, is exactly id: text or id: text(a..b).
  • No two fields in one block normalise to the same name.
  • Every range has both bounds; modifiers come after the type and before any =; no field has both @optional and a default.
  • @tag is inside a group, at most once, on a non-list text, int, bool or enum field.
  • Every $(Schema) and ref(Schema) names a declared schema; every default is valid for its own type.

Instances

  • Every header names a declared schema and has exactly one ::; every id is a valid identifier and unique after normalisation.
  • Clone statements sit directly under the header; no path is written twice in overlapping versions.
  • Text values containing ,, a leading [, # or ", a leading // or a spaced // are quoted; no value is quoted for an int, float or bool field.
  • Asset paths are relative, contain no .., and do not begin with assets/.
  • Every $name names a root scalar field of the same instance, or id.
  • Every required field has a value in every version in which it exists.

Logic

  • Every logic block names a declared schema, and no schema has two.
  • Every path operand starts with . or a loop variable; every condition is boolean.
  • Projected paths are used only with contains and exists; every require has an else throw "...".
  • derive? targets no field that declares a default; every version-scoped derive is guarded.
  • length() is applied only to list or text values; no nested loop reuses an enclosing variable name.

Then: abstract lint <project> exits 0, and abstract compile <project> JSON produces the expected document.

Things Abstract deliberately does not have

Imports and includes; free-key maps and dynamic object keys; user-defined functions, arithmetic and string concatenation; nested lists; a null literal; comments in the compiled output; output key renaming; a lenient mode; per-schema version axes; non-ASCII identifiers; list append or accumulation in logic.

When a task seems to need one of them, the answer is a different schema shape: a keyed list instead of a map, two named fields instead of a dynamic key, a clone instead of an import, a derive from a single expression instead of an accumulator.

The long form of this page, with worked examples and every reserved word, is docs/ai-primer.md in the repository. Notes for agents working inside the repository itself are in docs/ai/README.md.

The good AI workflow is simple: read the schema, edit the source, lint, compile, explain. Anything more clever should earn its keep.
