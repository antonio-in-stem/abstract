Logic blocks

Rules that need more than a type.

A logic block is where constraints that depend on relationships live: derived values, guarded requirements, and rules that differ between versions.

Docs
Language guide Types Schemas Instances Logic blocks Versions & overlays CLI Compiled data Java & bundles AI guide Diagnostics

Binding

logic Product {
    ...
}

A logic block attaches rules to a declared schema (E501 otherwise) and runs for every instance of that schema, and for every nested object validated against it. A schema may have at most one logic block (E502), and the block may live in a different .abt file from the schema.

The five statements

StatementEffect
derive .path = exprwrites a value onto the object being evaluated
derive? .path = exprwrites only when the path currently has no value
require cond else throw "msg"fails compilation with that message when the condition is false
if ... { } else if ... { } else { }branches; exactly one body runs
for $x in iterable { }runs the body once per element

Only derive and derive? mutate. Statements execute in source order.

A worked block

This is docs/examples/logic-basics.

logic Product {
    derive .shipping_class = standard
    derive? .release_wave = 1

    if .status == "active" {
        require .owner.contact exists
            else throw "Active products need an owner contact."
    } else if .status == "retired" {
        derive .visibility = hidden
    } else {
        derive .visibility = internal
    }

    derive .flag_count = length(.flags)

    require not .flags contains "banned"
        else throw "Banned products cannot ship."
}
Product :: @id.relic, @status.retired
    title: Relic
    owner.team: Knowledge Systems
{
  "template": "Product",
  "id": "relic",
  "title": "Relic",
  "status": "retired",
  "visibility": "hidden",
  "shipping_class": "standard",
  "release_wave": 1,
  "flag_count": 0,
  "owner": { "team": "Knowledge Systems" }
}

flags was never written, so length(.flags) is 0 — a path that resolves to no value is not an error here — and flags itself is omitted, because it is an absent optional list. visibility comes from the retired branch.

Paths and projections

.a.b starts at the object being evaluated; $x.a starts at a loop variable. A segment may carry a read-only index (.items[0].id) and may itself be a loop variable (.slots.$slot.mode). Every literal segment must name a declared field (E503).

A path that crosses a list field without an index projects: it resolves to one value per element. A projected path is a legal operand only of contains and exists.

require not .capabilities.id contains "banned"     // correct
require .capabilities.id != "banned"               // E519

That restriction is deliberate: the rejected line would otherwise silently mean “some element is not banned”, which is not what it reads like.

Operators

LevelConstructAssociativity
1 (tightest)( ... ), length( ... ), path, loop variable, version, literal—
2postfix exists—
3== != < <= > >= containsnon-associative
4prefix not, !right
5and, &&left
6 (loosest)or, ||left

So a or b and c is a or (b and c), and not .a == .b means not (.a == .b). To negate an operand instead, parenthesise it. Comparisons do not chain: a < b < c is E512.

Comparison semantics

SituationResult
an operand resolves to no valueevery comparison is false, including !=. Never an error.
two stringsequal only when identical, scalar for scalar. No case folding, no -/_ folding.
a number and a stringfalse, not an error
< <= > >= on non-numbersE513 — no string ordering, no numeric reading of strings
contains on a list / on a stringmembership / substring
comparing a list or an object with ==E513
a bare text path or a bare length(...) as a conditionE513 — there is no truthiness

Enum values are stored normalised, so .status == "active" is the correct spelling for an enum field, and "Active" is simply false rather than an error.

exists never touches the disk

exists is presence in the compiled data, for every field type, in every mode. It is true when the path resolves to at least one value and that value is not a single empty list — so an empty string is true and an absent optional field is false. On-disk existence of file and image assets is a schema check controlled by --skip-assets, which is exactly what keeps compiled data independent of that flag.

length and version

Argumentlength yields
a listthe number of elements
a stringthe number of Unicode scalar values
a projectionthe number of projected values
a path with no value0
a declared int, float, bool, group, $(Schema) or refE514, checked before any instance is read

version is the only built-in value: the integer version being compiled. It is a bare word with no . and no $, so it never collides with a field called version (written .version) or a loop variable ($version). This is docs/examples/logic-version:

versions 1..2

schema Item {
    name: text(1..40)
    glow: bool @since(2) = false
    schema_version: int(1..9)
}

logic Item {
    derive .schema_version = version

    if version >= 2 {
        derive .glow = true
    }
}

In version 1 the guarded derive does not execute, so writing glow — which does not exist there — never arises. An unguarded write against a field absent in the version being compiled is E521.

Loops and variables

for $lang in [es_es, es_mx] {
    require .copy.key contains $lang
        else throw "Missing $lang copy."
}

Loop variables are the only variables, always written $name. They are in scope inside their own block, may not shadow an enclosing loop (E516), and may be used as operands, as dynamic path segments, in derive values and in throw messages. A quoted string is never a variable: "$kind" is five characters. Iterating an absent or empty list runs the body zero times and is not an error.

What derive may write

TargetAllowed
a declared scalar field, or one inside a group or $(Schema)yes — missing intermediate objects are created
a list field, as a whole valueyes
one element of a list (.items[0].x)no — E506
.template, .idno — E504
a field the schema does not declareno — E505
a field absent in the version being compiledno — E521 when the statement executes
a path containing a loop variableno — E520

The right-hand side may be a literal, a string carrying interpolation, another path of the same object, length(...), version, or a loop variable. A path keeps the type of the value it resolved to; a path that projects several values is E519. There is no accumulation operator and no list append: a list is assigned in the instance, or derived once from a single expression.

derive? writes only when the path currently has no value. Because defaults are filled before logic runs, a derive? on a field that declares a default could never fire, and is E518.

Order of evaluation

For one object and one version:

  1. authored values are type-checked;
  2. defaults are filled;
  3. logic runs — nested schema logic first, in field declaration order and element order, then this schema’s block;
  4. required fields are checked, so a derive may satisfy one;
  5. the whole object is re-validated from scratch, so nothing logic wrote escapes validation.

A failed require aborts that instance immediately with E515 and your own message; no later statement in that instance runs, and compilation fails.

data/templates/Pack.abt:32:9: error[E515]: Sticker logic: Epic stickers must carry the promo tag.
  note: data/stickers/ember.ab:1:1: instance 'ember' declared here.
  note: compiling version 1.

Use schema fields for shape and type. Use logic when the rule depends on relationships between fields, or between a field and the version being compiled.

Determinism

Logic evaluation is a pure function of the authored object, the schema set and the version. It performs no I/O, does not observe the filesystem, the clock, the locale or the environment, and visits statements, branches, loop elements and nested objects in a fixed order. Two runs on the same bytes produce the same result, including the same first failing require. A diagnostic raised inside a loop additionally names the index and the item.
