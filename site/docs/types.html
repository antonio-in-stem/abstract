Type reference

Every value knows what it is.

Abstract keeps the authored type all the way to the output: integers stay integers, decimals stay floats, booleans stay booleans, and images are checked against their real bytes.

One schema using all nine

This is docs/examples/types-tour, stored with the document it compiles to.

schema Owner {
    team: text(1..50)
    contact: text(1..80)
}

schema Pack {
    title: text(1..40)
}

schema Product {
    title: text(1..60)
    replicas: int(1, 3..12)
    price: float(0..9999)
    featured: bool
    status: enum(draft, active, retired)
    manual: file(txt, pdf)
    icon: image(png 32x32)
    pack: ref(Pack)
    owner: $(Owner)
}
Product :: @id.atlas, @status.Active
    title: Atlas Search
    replicas: 3
    price: 19.5
    featured: true
    manual: docs/atlas.txt
    icon: ./icons/atlas.png
    pack: core
    owner.team: Knowledge Systems
    owner.contact: systems@example.com
{
  "template": "Product",
  "id": "atlas",
  "title": "Atlas Search",
  "replicas": 3,
  "price": 19.5,
  "featured": true,
  "status": "active",
  "manual": "docs/atlas.txt",
  "icon": "./icons/atlas.png",
  "pack": "core",
  "owner": {
    "team": "Knowledge Systems",
    "contact": "systems@example.com"
  }
}

Note @status.Active compiling to "active": an enum value is normalised, so case and -/_ differences in the source disappear. Note also that owner appears last because that is where the schema declares it, not because it was written last.

Ranges

WrittenMeaning
int(7)exactly 7
int(2..15)a closed interval
int(1, 3..12)satisfied by at least one part — 1, 3 and 12 pass, 2 does not
int(5..), int(..5)E305: both bounds are required
int(10..5)E305: reversed, rejected at the schema, not at some later instance
text(-5..-1)E318: unsatisfiable

A text range counts Unicode scalar values, not bytes and not grapheme clusters: an emoji with a skin-tone modifier counts as 2.

Numbers do not substitute for one another

replicas: 3            // int field: fine
replicas: 3.0          // E412 - a float literal is not an int value
price: 19.5            // float field: fine
count: "5"             // E412 - quoting never coerces, for any numeric type
version_text: 1.21.5   // on a text field: the string "1.21.5"; two dots is not a number

Write every float value with a fractional part. A float always renders with one — 3 becomes 3.0 — so writing it that way in the source keeps the source and the output reading alike.

Assets: file and image

Both name assets under <project root>/assets. There is one resolution rule: strip one leading ./, then resolve relative to assets/.

WrittenResolves to
./textures/a.pngassets/textures/a.png
textures/a.pngassets/textures/a.png
./assets/textures/a.pngassets/assets/textures/a.png — the prefix is not special-cased
../secret.png, /etc/x, C:\xE424

file checks the extension and, unless --skip-assets, that the file exists. It never inspects contents. image additionally reads a bounded header prefix — at most 64 KiB, never decoding pixels — to confirm the real format and the dimensions.

schema Sticker {
    icon: image(png 128x128)
    hero: image(png 1920x1080, jpg 1920x1080) @optional
    wide: image(png 1024x*) @optional
}
CheckError
extension not declared by the fieldE420
file missing on diskE421
content does not match the extension (a GIF renamed .png)E422
dimensions match no declared alternativeE423

Supported formats are png, jpg, gif, bmp and webp; jpeg canonicalises to jpg, so file(jpg, jpeg) is E319 and every diagnostic spells it jpg. * on either side of a size token means “any”.

--skip-assets skips exactly E421, E422 and E423. It never skips the extension check, the path-confinement check, or any type, range, enum, reference, required-field or logic check — and the compiled bytes are identical with and without it.

References between instances

schema Sticker { pack: ref(Pack) }
Sticker :: @id.dragon
    pack: winter_2026
{ "template": "Sticker", "id": "dragon", "pack": "winter_2026" }

The value is the id of another instance, normalised like every id. The target must exist (E431), must use the named schema (E432), and must exist in the version being compiled. The referenced object is never inlined. A list of references is written refs[]: ref(Pack). Wildcards do not apply to ref fields.

Nested objects

Use $(Schema) when the same shape appears in more than one schema, and an inline group when the shape exists only here. They validate identically; the difference is reuse and whether a logic block can attach (only a named schema can have one).

schema Product {
    owner: $(Owner)        // reusable, may have its own logic block
    limits {               // inline, exists only here
        soft: int(0..100)
        hard: int(0..100)
    }
}

A nested object carries no template and no id: those belong to root objects. Inside a group, id and template are therefore ordinary field names, which is why id: enum(...) @tag is the usual spelling of a keyed list.

The normative text is docs/SPEC.md; these pages explain it.
