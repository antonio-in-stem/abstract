Type reference

Every value knows what it is.

Abstract keeps the authored type all the way to the output: integers stay integers, decimals stay floats, booleans stay booleans, and images are checked against their real bytes.

Every type accepts [] for lists, = value for defaults, and @optional. Constraint parentheses are optional for text, int, and float.

text

Ranges count characters (not bytes), so accented and non-Latin text measures the way a human would count it.

name: text(1..80)
short_code: text(2, 4..8)     // exactly 2, or 4 to 8 characters
notes: text @optional         // any length

Unquoted values become text when they are not numbers or booleans. Quote anything with commas, deliberate casing, or characters that would otherwise be parsed: desc: "Hello, world". Strings support \", \\, \n, \t, and \r escapes.

A value like 1.21.5 stays text automatically (two dots is not a number), but 1.5 is a float. When a text field receives a number, the compiler asks you to quote it instead of guessing.

int

Whole numbers with exact values and inclusive ranges, in any mix:

variant_count: int(0, 2..15) = 0
release_year: int(2000..2100)
priority: int               // any integer

float

Decimal numbers. Instances write plain literals; integers are accepted and widened.

price: float(0..9999) = 0.0
opacity: float(0..1)
scale: float = 1.0
Item :: @id.coin
    price: 9.5
    opacity: 0.85

The compiled output keeps them as numbers: "price": 9.5. Scientific notation (2.5e3) is accepted; inf and nan are not values.

bool

true and false are real booleans in the output. Header tags have a shorthand: a bare @flag means true.

tradable: bool = true
featured: bool
Item :: @id.star, @featured        // featured: true
    tradable: false

enum

A closed vocabulary. Values normalize to lowercase snake case, so Legendary, legendary, and LEGENDARY are the same member. Unknown values fail with a suggestion.

rarity: enum(common, rare, epic, legendary)
flags[]: enum(hat_overrides_helmet, hat_has_variations) @optional

List fields accept wildcard members that expand against the vocabulary:

flags: hat_*      // becomes every enum member starting with hat_

file

A path with an approved extension. When compiling from disk, the file must exist. Relative paths resolve under the project assets/ folder; paths that already start with ./assets/ resolve from the project root.

texture: file(png)
document: file(pdf, md)

image

image(...) is file(...) plus real media validation. The compiler opens the file and reads only the header bytes (26 bytes for a PNG, a handful of segment headers for a JPG) to learn the true format and dimensions. Pixels are never decoded, so validating hundreds of textures costs almost nothing.

icon: image(png 128x128)                  // exactly 128x128 png
hero: image(png 1920x1080, jpg 1920x1080) // either container
thumb: image(png 64x*)                    // fixed width, any height
art: image(png, jpg, gif, bmp, webp)      // any size, checked signature

Three distinct failures are caught at compile time:

  • Wrong extension: the path extension is not one of the declared formats.
  • Lying content: the file is named .png but its bytes are GIF data (a re-exported or renamed asset). The error names both formats.
  • Wrong size: the header dimensions do not match any declared alternative. The error shows the actual size.

Supported containers: PNG, JPG, GIF, BMP, and WebP (lossy, lossless, and extended). Use --skip-assets to compile on machines that do not have the binary assets checked out.

References and groups

$(Name) validates a nested object against another schema; groups declare the shape inline. Both emit objects ordered by their schema fields.

schema Slot {
    mode: enum(generate, custom) @tag
    distribution[]: file(png) @optional
}

schema Sticker {
    slots {
        1: $(Slot)
        2: $(Slot) @optional
    }
}

Strictness

Instances may only assign fields the schema declares. A typo fails with the closest declared name:

stickers/typo.ab: Unknown field 'rarty' at Sticker. Did you mean 'rarity'?
Declared fields: id, rarity, origin, ...

Pass --allow-unknown to the CLI (or set allow_unknown_fields in the library) if you need the lenient behavior during a migration.
