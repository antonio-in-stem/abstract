Command line

A parser that refuses to guess.

Four commands, three flags, four exit codes, and a rule that nothing is ever silently ignored — not a stray positional, not a mistyped format keyword, not a flag it does not know.

Invocation

abstract <command> [positional ...] [flags ...]

The argument parser is strict. Every token must be recognised: an unknown command is E801, an unknown flag E802, a flag missing its value E803, an extra or unrecognised positional E804. Nothing is ever silently ignored. Flags may appear anywhere among the positionals. A command word is always required — there is no direct form.

Commands

abstract init m-project
abstract compile m-project JSON
abstract compile m-project YML --out m-project.yml
abstract lint m-project
abstract templates m-project

compile resolves the project, compiles it and renders the document. The path is either exactly one directory or one or more .ab files; mixing them, or naming paths that belong to different projects, is E807. A named directory must be the project root or the data directory — a directory inside the data directory is E806.

lint performs exactly the same work, including asset checks, and renders nothing. It writes nothing to stdout and, on success, one line abstract: ok to stderr.

templates prints the schema names of the project, one per line, sorted. It runs the discovery, parse, table and schema-validation phases, so a project whose schemas are broken fails instead of printing a partial list.

init scaffolds a project that compiles out of the box. The target directory must be empty (E813).

Output formats

KeywordRendering
JSONthe default; two-space indent
YML / YAMLblock style, every mapping key quoted
RAWfour-space indent, bare keys; a review format, not machine-parsed

Any other keyword is E805. Detail: compiled data.

Flags

FlagMeaning
--out <file> / --out=<file>write the document to a file instead of stdout
--skip-assetsskip on-disk asset checks
--max-errors <n>report at most n diagnostics; default 20, 0 means no limit

A flag given twice is E811. A flag value must not begin with -, so --out --skip-assets is E803 rather than a request to write a file with that name; a destination that genuinely begins with - is written --out=-name or --out ./-name. --max-errors requires a decimal integer ≥ 0 (E812), and bounds reporting only: it never changes which diagnostic comes first and never changes the exit code.

--out

The destination is used exactly as written; no extension is appended or checked. It is refused with E808 when it is a discovered source file, when it lies inside the data directory, or when its extension is .ab or .abt and it lies inside the discovery root. A compiler never overwrites its own inputs and never writes a file it would read on the next run.

abstract compile m-project JSON --out m-project/out.json    # fine
abstract compile m-project JSON --out m-project/data/x.json # E808

When --out is given, nothing is written to stdout; one informational line naming the path and the format goes to stderr. The bytes written are exactly the bytes that would have gone to stdout. A write failure of any kind is E810 and exit code 3.

--skip-assets

It skips exactly three checks and nothing else: for file values the on-disk existence check (E421); for image values the existence check, the header probe (E422) and the dimension check (E423).

It does not skip the extension check (E420), the path-confinement check (E424), or any type, range, enum, reference, required-field or logic check, and it has no effect on exists, which never touches the filesystem in any mode.

The compiled bytes are identical with and without --skip-assets. The flag changes which errors are reported, never what is emitted. An implementation that lets the flag alter output is non-conforming.

Exit codes

CodeMeaning
0success
1compilation failed: at least one E1xx–E7xx diagnostic
2usage error: an E8xx diagnostic other than E810
3output could not be written (E810)

stdout and stderr

stdout carries only the rendered document, the schema list, or the usage and version text. It is never mixed with diagnostics; stderr carries every diagnostic, note and informational line. If the reader closes stdout — piping into head, for instance — the process terminates quietly with exit code 0. Output is UTF-8 with LF line endings on every platform, with no BOM.

Diagnostics

<path>:<line>:<col>: error[<ID>]: <message>
  note: <note text>
data/products/atlas.ab:4:5: error[E409]: Unknown field 'rarty' in atlas. Did you mean 'rarity'?
  note: declared fields: title, status, rarity, owner.

The path is project-relative with / separators — absolute, canonical and extended-length platform paths never appear. Line and column are 1-based, and the column counts Unicode scalar values. The message is one sentence ending with a period, followed by zero or more notes indented two spaces, each naming a second position where it refers to one. Every identifier is catalogued in diagnostics and is stable across 1.x releases.

Project resolution

m-project/            <- project root
  assets/
  data/               <- data directory, and the discovery root
    templates/Product.abt
    products/atlas.ab
InvocationResult
abstract compile m-projectthe whole project
abstract compile m-project/datathe same source set
abstract compile m-project/data/products/atlas.abthe same project, emitting only that file’s instances
abstract compile m-project/data/productsE806 — name the project root or the data directory

Discovery skips directories whose name starts with ., and node_modules, target, build and out. Symbolic links are resolved and each canonical directory is visited once, so link cycles terminate. A project with no source files is E103.

Optional commands

bundle and unbundle ship with the reference implementation, operate on an already-compiled document, and are not part of the language: a conforming implementation need not provide them. See Java & bundles.
