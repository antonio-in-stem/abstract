Language guide

The shape of Abstract.

Abstract has two author-facing file types. .abt files define schemas. .ab files define instances. The compiler reads both and emits validated JSON, YAML, or RAW data, and can seal the result into encrypted bundles for applications.

The mental model

A schema is a class of data. It says which fields exist, what type each field accepts, which values are allowed, and which defaults fill in missing pieces. An instance is one concrete object. The compiler validates the object, normalizes it, and emits JSON or YAML.

That makes Abstract more specific than JSON and less broad than a general programming language. It is a language for authored data: data that gets reviewed, translated, versioned, generated, and eventually consumed by other systems.

File types

schema Product {
    id: text(1..40)
    status: enum(draft, active, retired)
    release_year: int(2000..2100)
}

Schema files use the .abt extension. Instance files use .ab:

Product :: @id.atlas, @status.active
    release_year: 2026

Compiled data is printed by default. Add true as the final CLI argument when you want Abstract to write a sibling .json or .yml file.

Schemas

A schema starts with schema Name { ... }. Field names are normalized to lowercase snake case. Fields can be text, int, float, bool, enum, file, image, references to other schemas, nested groups, and lists, with defaults, optional markers, and tags. The full catalog lives in the type reference.

schema Service {
    id: text(1..40)
    tier: enum(free, standard, premium)
    replicas: int(1..12) = 1
    price: float(0..999) = 0.0
    public: bool = false
    icon: image(png 128x128) @optional
    notes: text(1..120) @optional
}

Instances

An instance starts with Template ::. Header tags are a concise form for simple field assignments. Longer values can be placed below the header with normal assignment syntax.

Service :: @id.search, @tier.premium
    replicas: 3
    notes: "Runs on the public cluster."

Groups and lists

Groups are nested objects. A group field ending in [] becomes a list of objects.

schema Product {
    owner {
        team: text(1..50)
        contact: text(1..80)
    }

    capabilities[] {
        id: enum(search, sync, export) @tag
        availability: enum(alpha, beta, stable) = stable
    }
}

Tags

@tag marks the field that a shorthand tag fills. If id is tagged, #search means {id: "search"}. Tag calls can also include overrides.

capabilities: [#search, #sync(availability: beta)]

Paths, tables, and expansion

Dotted paths assign nested fields, tuple arrays make small tables pleasant to read, and wildcard expansion lets a tagged enum family expand without repeating every member.

owner.team: Platform
copy(key, value): (en_us, "Hello"), (es_*, "Hola")
thresholds.{warning, critical}: 90

Cloning: the template-instance heart

Clone syntax copies a previous instance and applies overrides. It is meant for families of data that share most fields but differ in a few intentional places. &id.* clones everything; &id.field.path clones one subtree; several clone lines merge in order, later clones winning per field.

&atlas.*                 // start from all of atlas
&pricing_2026.tiers      // then borrow just the tiers subtree

Product :: @id.beacon, @status.draft
    name: Beacon Export

Interpolation

Strings and paths can reference the instance's own scalar fields with $field or ${field}. Values resolve after clone overrides, which is what makes cloned families point at their own assets. $$ writes a literal dollar sign.

Product :: @id.red_dragon
    icon: ./textures/item/sets/$id/icon.png

Strict by default

The compiler rejects fields the schema does not declare (with a "did you mean" suggestion), duplicate instance ids, and duplicate schema names. Values keep their authored types all the way to the output: 9.5 is a number, true is a boolean, and 1.21.5 stays text.

Current boundaries

Version 0.2.0 stays deliberately small. logic blocks derive values, branch with if / else if / else, loop, and validate relationships, but they are not a general programming language. Outputs are JSON, YAML, RAW, and sealed .abx bundles for the Java runtime. The priority remains a small, stable language with standard readable output.
