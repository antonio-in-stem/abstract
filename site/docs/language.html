Two kinds of file

ExtensionKindContains
.abttemplateschema declarations, logic blocks, at most one versions line
.abinstanceconcrete objects, each validated against a schema

A template file must not contain instances and an instance file must not contain schemas or logic; either way round it is E210. The compiler reads both, validates everything, evaluates logic, and emits one compiled document.

Four principles

PrincipleWhat it decides
MinimalOne way to express each thing. No imports, no free-key maps, no user-defined functions, no arithmetic, no nested lists, no comments in output.
ElegantAuthored source is shorter and more readable than the JSON it compiles to.
DeterministicThe same input bytes produce the same output bytes on every machine, in every locale, in any argument order.
StrictEvery construct is defined or an error with an identifier and a position. Nothing is silently ignored, coerced or dropped.

Project layout

m-project/            <- project root
  assets/
    textures/atlas.png
  data/               <- data directory, and the root of source discovery
    templates/Product.abt
    products/atlas.ab

The compiler walks up from the path you name until a directory called data appears; the project root is that directory’s parent, and assets live in <project root>/assets. A project may also keep its sources in one plain directory with no data/ at all.

abstract compile m-project
abstract compile m-project/data
abstract compile m-project/data/products/atlas.ab

All three compile the same source set. Naming a directory inside data/ is E806: it would silently compile more than it names.

Schemas

schema Product {
    title: text(1..60)
    status: enum(draft, active, retired) = draft
    price: float(0..9999)
    owner {
        team: text(1..50)
        contact: text(1..80) @optional
    }
    capabilities[] {
        id: enum(search, sync, export) @tag
        availability: enum(alpha, beta, stable) = stable
    }
}

A schema is a name and a block of fields. Names are unique project-wide. The declared order of fields is the key order of the output, so a schema is also a layout. Full detail: schema authoring and types.

Instances

Product :: @id.atlas, @status.active
&base_product.*
    title: Atlas Search
    owner.team: Knowledge Systems
    capabilities: [#search, #export(availability: alpha)]

An instance is a header, then zero or more clone statements, then body statements and body blocks. Indentation is conventional and carries no meaning. A line is a header only when its first token is a schema name and the next token is ::, so window: 12::30 stays an ordinary assignment.

Full detail: instance authoring.

The three rules that catch everyone

A comma always separates list items

caption: "Hello, world"       // one string
caption: Hello, world         // a two-item list; E412 on a non-list field

At bracket depth 0 a , is a list separator whatever the field’s declared type, because the parser has no type information. A trailing comma at depth 0 is E442: a statement never continues onto the next line on a comma.

Quoting never coerces

count: 5                      // int
count: "5"                    // E412 - quoting does not coerce
caption: "19.5"               // on a text field: the string 19.5

Three characters are reserved at the start of a value

First characterMeaningTo write it literally
[starts a listquote the value
#starts a tagged objectcolor: "#ff0000"
"starts a quoted stringquote the whole value

Logic

logic Product {
    derive .shipping_class = standard
    derive? .release_wave = 1

    if .status == "active" {
        require .owner.contact exists
            else throw "Active products need an owner contact."
    } else if .status == "retired" {
        derive .visibility = hidden
    } else {
        derive .visibility = internal
    }

    require not .flags contains "banned"
        else throw "Banned products cannot ship."
}

Logic attaches rules to a schema and runs for every instance of it, and for every nested object validated against it. Paths start with .; there is no truthiness; string comparison is exact. Full detail: logic blocks.

Versions

versions 1..3

schema Item {
    name: text(1..40)
    glow: bool @since(2) = false
    legacy_tint: int(0..255) @removed(3) @optional
}

One project carries every version of its data. @since(n) and @removed(n) scope a field, a body statement or a whole instance. The compiled document holds the newest version in data and every earlier difference in overlays. Full detail: versions and overlays.

Output

Three renderings of the same tree: JSON (two-space indent), YAML (every mapping key quoted) and RAW (four-space indent, bare keys, for review). Objects begin with template and id, then the schema’s fields in declaration order; instances are ordered by (template, id). Absent optional fields are omitted in every format, including lists, and there is no null. Full detail: compiled data.

What Abstract deliberately lacks

Imports and includes, free-key maps, user-defined functions, arithmetic, nested lists, a null literal, comments in output, output key renaming, a lenient mode, per-schema version axes, non-ASCII identifiers, and list accumulation in logic. When a task seems to need one of them, the answer is a different schema shape: a keyed list instead of a map, two named fields instead of a dynamic key, a clone instead of an import.

The normative text is docs/SPEC.md; these pages explain it.
