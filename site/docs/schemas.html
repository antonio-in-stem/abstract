Schema authoring

Put the rules where authors can see them.

Schemas are the contract. They should be strict enough to catch mistakes and plain enough that a teammate can read them without a compiler course.

Schema declaration

schema Product {
    id: text(1..40)
    name: text(1..80)
}

The schema name is emitted as template in RAW. Field order in the schema also controls field order in the output, which keeps diffs and reviews stable.

Supported types

TypeUse it forExample
textStrings with character length limits.name: text(1..80)
intWhole numbers with allowed ranges or exact values.replicas: int(1, 3..8)
enumA closed vocabulary that normalizes to lowercase snake case.status: enum(draft, active)
filePaths with approved extensions.image: file(png, jpg)
$(Name)A nested object validated by another schema.owner: $(Owner)

Ranges

text ranges count characters. int ranges validate the numeric value. A range can be exact or inclusive.

short_code: text(2, 4..8)
version_support: int(1..3)

Defaults and optional fields

Defaults are inserted when a field is missing. Optional fields may be omitted. Optional list fields compile to an empty array when missing, which makes downstream consumers simpler.

status: enum(draft, active, retired) = draft
notes: text(1..160) @optional
tags[]: enum(core, public, internal) @optional

Lists

Add [] to the field name. Scalar lists accept arrays of values. Group lists accept arrays of objects or tagged shorthand objects.

tags[]: enum(core, public, internal)

capabilities[] {
    id: enum(search, sync, export) @tag
    availability: enum(alpha, beta, stable) = stable
}

Groups

A group is an inline object. Groups are best when the nested fields only make sense inside the parent schema.

owner {
    team: text(1..50)
    contact: text(1..80)
}

References

Use $(OtherSchema) when a nested shape deserves its own name and may be reused in several schemas.

schema Address {
    line: text(1..120)
    country: text(2..80)
}

schema Office {
    id: text(1..40)
    address: $(Address)
}

Tags

A field marked @tag can be filled with #value shorthand inside instance lists. The tag field is usually id, but it does not have to be.

steps[] {
    mode: enum(generate, custom, inherit) @tag
    weight: int(1..100) = 1
}

Good schemas are not maximal schemas. Start with the rules that catch real mistakes. Add more only when the data starts asking for them.

After the schema feels right, move to instance authoring.
