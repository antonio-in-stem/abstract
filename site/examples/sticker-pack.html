Example

Sticker pack.

Two schemas, four instances, and almost every construct in the language — including two versions reduced into a single overlay.

Examples
All examples Product catalog Release policy Sticker pack

Project: docs/examples/sticker-pack, which is the worked example of the specification’s Appendix C. It exercises an explicit id declaration, groups, a reference, a keyed list, defaults, two versions, an instance window, a clone, interpolation, wildcards, tuple arrays, logic and overlays — in about forty lines.

Layout

sticker-pack/
  assets/
    textures/
      frost.png            128x128 PNG
      ember.png            128x128 PNG
  data/
    templates/
      Pack.abt
    packs/
      winter_2026.ab
      spring_2026.ab
    stickers/
      frost.ab
      ember.ab

data/templates/Pack.abt

versions 1..2

schema Pack {
    id: text(3..24)
    title: text(1..40)
    tier: enum(free, plus) = free
    slot_count: int(1..9) @optional
}

schema Sticker {
    pack: ref(Pack)
    title: text(1..60)
    icon: image(png 128x128)
    rarity: enum(common, rare, epic) = common
    glow: bool @since(2) = false
    tint: int(0..255) @optional @removed(2)
    owner {
        team: text(1..40)
        contact: text(1..60) @optional
    }
    tags[]: enum(core_ui, core_game, promo) @optional
    copy[] {
        key: enum(en_us, es_es, es_mx) @tag
        value: text(1..80)
    }
}

logic Sticker {
    derive? .owner.contact = support@example.com

    if .rarity == "epic" {
        require .tags contains "promo"
            else throw "Epic stickers must carry the promo tag."
    }

    for $lang in [es_es, es_mx] {
        require .copy.key contains $lang
            else throw "Missing $lang copy."
    }
}

The two packs

Pack :: @tier.plus
    title: Winter 2026
    slot_count: 3
Pack :: @since(2)
    title: Spring 2026

Neither header carries @id, so each id comes from its file stem: winter_2026 and spring_2026. Both are 11 Unicode scalar values, so both satisfy the declared id: text(3..24).

@since(2) at the end of the second header is an instance window, not a header tag — the identifier is followed immediately by (, and that one character is the whole distinction. spring_2026 exists in version 2 only.

The two stickers

Sticker :: @id.frost, @rarity.rare
    pack: winter_2026
    title: Frost
    icon: ./textures/$id.png
    tint: 200
    owner.team: Studio A
    tags: core_*
    copy(key, value): (en_us, Frost), (es_*, Escarcha)
Sticker :: @id.ember, @rarity.epic
&frost.*
    title: Ember
    tags: [core_ui, promo]
    copy(key, value): (en_us, Ember), (es_*, Brasa)

Every non-obvious step

  1. $id interpolates to frost, so icon resolves to assets/textures/frost.png, which must be a 128x128 PNG or the compile fails with E422 or E423.
  2. core_* expands, in the enum’s declared order, to core_ui, core_game.
  3. es_* clones the whole tuple row into es_es and es_mx, keeping the other cell.
  4. tint exists only in version 1, so the statement that assigns it applies only there. No annotation is needed: a statement’s applicability set is clipped to its field’s existence set.
  5. ember clones frost’s authored data, including the raw text ./textures/$id.png. Interpolation runs after cloning, so ember’s icon becomes ./textures/ember.png.
  6. Ember’s own header and statements then override rarity, title, tags and copy by plain assignment — a keyed list an instance writes itself replaces the cloned one rather than merging with it.
  7. derive? .owner.contact fires for both stickers, because contact is optional with no default.
  8. Ember is epic, so the guarded require runs and its promo tag satisfies it.

And the overlay for version 1

"overlays": [
  {
    "versions": { "min": 1, "max": 1 },
    "data": [ /* ember and frost, each carrying tint: 200 and no glow */ ],
    "removed": [ "spring_2026" ]
  }
]

The project range is 1..2, so the base is version 2 and the only version to reduce is 1. ember and frost each differ from the base throughout 1..1 — they carry tint and lack glow — and spring_2026 does not exist in version 1 while the base carries it, so it becomes a removal over the same range. All three entries share the range, so they land in one overlay. winter_2026 has no version-scoped field and no window, so it is identical in both versions and appears in no overlay.

A consumer running version 1 applies that one overlay: replace ember and frost, delete spring_2026, keep winter_2026 from the base. A consumer running version 2 matches no overlay and uses data unchanged.

The complete byte-exact document, including the elided overlay objects, is in docs/examples/sticker-pack/expected.json.

A failing compile

Change ember’s tags to tags: [core_ui] and the guarded require fails:

data/templates/Pack.abt:32:9: error[E515]: Sticker logic: Epic stickers must carry the promo tag.
  note: data/stickers/ember.ab:1:1: instance 'ember' declared here.
  note: compiling version 1.

Version 1 is named because versions are compiled in ascending order and the same require fails in both.
